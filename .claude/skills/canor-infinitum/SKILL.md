# /canor-infinitum: Mathematical Organization Theory

Frames Canor™ work as an **MOT Program**: it places each request in its phase, sets the perspective that phase works from, collects the participants, category, status and budgets, and hands each artifact to the language skill that builds it.

## The MOT pipeline

A **Strategy** is the core unit, but it is useless without a **Flow** / **MetaFlow**. Together they are represented as a **Soul** or an **Action**. All of these together form a **Maneuver**, which is datamined for orthonormalization / orthogonality and stored as a **United** Meta-Schema. Multilateral United Meta-Schemas establish an **Elite** Programming / Diffeomorphic Basis, used to *assemble* a Quantum-Linguistics program. Then the **Follower** Interlingua compiles it with plug-and-play Complementary Languages, and everything is stored in the **Aether** Intermediate Representation, Timing Library + Library Linker, and ε-error Mitigation Tool.

## Choose a mode

| The request | Mode |
|---|---|
| Bare `/canor-infinitum`, or no phase is named | **Orient** |
| One phase is named, or one artifact | **Frame** |
| Several phases, or a program from start to finish | **Walk** |
| "Where are we", progress, completion, assignment | **Status** |

A phase is **named** when the user explicitly uses one of its terms: Strategy, Flow, MetaFlow, (Meta)Flow → A · Soul, Action → B · Maneuver → C · United, Meta-Schema, Interchange → D · Elite, Diffeomorphic Basis, Quantum-Linguistics → E · Follower, Interlingua → F · Aether, Intermediate Representation, IR, Timing Library, ε-error, Error Mitigation → G. Only explicit mentions count. Don't infer a phase from a loose synonym.

### Orient
Summarize the pipeline in three or four lines. Then ask the user which phase the work is in. Offer the four most likely phases. A–G that don't fit go in "Other".

### Frame
1. **Open with the phase's framing statement** (below). Adapt it to the task, keep its substance, and keep it to one short paragraph.
2. **Establish the phase record** (the next section). Ask only for what's missing, batched into a single prompt.
3. **Hand off** to the phase's skill with the collected values, so it doesn't ask again. If the user only wanted framing, design or a brief, stop at the record.

### Walk
Apply the phases in pipeline order A → G. For each one: a single framing line, its record, and the **handoff**, meaning exactly which artifact the next phase consumes (e.g. "the Maneuver Group `onboard` becomes the body of the United object"). A phase whose input doesn't exist yet is **blocked**. List it with what it waits for. Don't skip it, and don't run ahead of it.

### Status
Recurse every MOT prerequisite of the named program or Maneuver (Strategies, (Meta)Flows, Actions, Souls, Maneuvers, United objects, bases, compilations). Look for them in the workspace `.<project>/<language>/`. For each one, report whether it was found or is missing, its completion (complete / incomplete), its assignment (**assigned**, **tasked**, **scheduled**, **unassigned**), and its diagnostics. A missing prerequisite is `CANOR_ERR_NOT_FOUND`, listed, not omitted. For build, test and error-log detail, hand off to `/aether`.

## The phase record

Every Frame, Walk and Status output uses this record, one per phase. A field that doesn't apply is `n/a`. A field nobody has decided yet is `unset`, which is an open item, not a guess.

| Field | Values |
|---|---|
| Phase | A … G |
| Perspective | The phase's perspective (below) |
| Participants | User, App, Agent. Internal or external |
| Signatories | Phases D–G: at least two consenting parties |
| Category | Storage, Learning, Operation (Soul / Action) |
| Completion | complete, incomplete |
| Assignment | assigned, tasked, scheduled, unassigned |
| Concurrency | sequential, concurrent, asynchronous |
| Budgets | Phases D–G: per-category ε-error allowances, latency, jitter, update rate |
| Agreement | Phases D–E: accepted, rejected, incomplete, undefined |
| Artifacts | `.<project>/<language>/<name>.fwh` / `.fwb`, existing or to create |
| Diagnostics | `CANOR_*` code and message, every one kept |
| Open items | Everything `unset` or profile-defined |
| Next | The skill that takes the next step |

**Budgets are integers.** ε-error allowances are per error category, as closed integer intervals: a basis bound `B[c]`, each signatory's allowance `A[s][c] ⊆ B[c]`, and its measured orthonormalization error `E ⊆ A`, the same form `/united` and `/elite` use. Latency and jitter are integer ticks or `[LO, HI]` intervals, and the update rate is in ops/sec. Fixed-point values are over `CANOR_ONE = 1000`. If a value would need a fraction, rescale it and say so.

**Agreement is unanimous.** A D or E record is `accepted` only when every signatory has ratified, certified and approved the same digest, version and basis. Any rejection makes it `rejected`, and any pending step makes it `incomplete`. An `unset` digest or signature algorithm makes it `undefined` (`CANOR_ERR_UNDEFINED`). Never accept by default. Adding or removing a signatory voids earlier approvals.

## Framing statements

### A: Strategy / (Meta)Flow
**Perspective:** System Architecture & Experience domain (system-level observer, sensory/perceptual mapping).
> We're now engaging within the System Architecture & Experience domain, for formal UX/perceptual detailing work. The task is to detail a concurrent, and possibly asynchronous, MOT Program: within already existing Flows or Strategies, as a whole new (Meta)Flow with a whole new Strategy, or as a standalone Flow or a standalone Strategy.

Establish: which of those four shapes it is, which Action it engages (System / User Action, or App / Agentic Action), and its concurrency.

### B: Soul / Action
**Perspective:** Computational Subject, Agent, or Participant domain (formal observer perspective).
> We're now engaging from a Computational Subject, Agent, or Participant perspective, for responsivity mapping with interaction-detailing work. We'll be detailing concurrent, and possibly asynchronous, Soul and / or Action representations as an MOT Program, both subjective and objective.

Establish: whose Soul it is (User / App / Agent), its category (Storage / Learning / Operation), and whether each representation is subjective or objective. An unassigned category is `CANOR_ERR_UNDEFINED`, listed as an open item.

### C: Maneuver
**Perspective:** the User / App / Agent completing the Maneuver.
> Recollect and recurse all formal MOT prerequisites that belong to this Maneuver (Strategies, (Meta)Flows, Soul or Action representations, et cetera) as a subjective or objective MOT Program of incomplete or complete status, with regard to a User's / App's / Agent's completion of the Maneuver.

Establish: the recursed prerequisite list, completion, and assignment (assigned / tasked / scheduled / unassigned).

### D: United / Meta-Schema
**Perspective:** the signatories.
> Two or more parties have bilaterally or multilaterally signed this document for processing, each within its own error-metric allowance budget, to generate an MOT Program result based on Elite Programming / Diffeomorphic Basis / Quantum-Linguistics. In effect, each signatory requests that an MOT Program be **assembled** from its own orthonormalized, and therefore dataset-independent, United datasets or Meta-Schemas.

Establish: the signatories and their roles, the error categories, each signatory's allowance `[LO, HI]` per category, and the orthonormalized datasets they bring. Then hand off to `/united`.

### E: Elite / Diffeomorphic Basis / Quantum-Linguistics
**Perspective:** the signatories, jointly.
> We've asserted and acclimated our multilateral coordination surfaces for complementary cooperation. This fulfills our signatory contract of exploring and exploiting our datasets from a shared, common categorical preliminary. Each of us has orthonormalized our own dataset within ε-error metrics, and we hold an orthogonal United Meta-Schema for further processing. Now it is time to synchronize and transcend these independent datasets, and *assemble* a Diffeomorphic Basis / Quantum-Linguistics MOT Program that every signatory can agree on.

Establish: the shared United digest, the basis bounds `B[c]`, and the agreed latency metrics, jitter coefficients, error-rate allowances and update-rate budget. Then hand off to `/elite`, mode B, for the unanimity protocol.

### F: Follower / Interlingua
**Perspective:** each signatory, separately.
> Every signatory holds its Elite Programming / Diffeomorphic Basis / Quantum-Linguistics and is ready to compile its own program with its own Complementary Language plug-ins (FPC/Lazarus, SWI-Prolog & C, Rust FFI), using the Follower Interlingua targeting Zephyr RTOS or sandboxed native environments. The result is either a compiled object, ready to execute on demand, or, when compilation fails, an Intermediate Representation with that signatory's error report and plug-ins. Every signatory was handed a valid United Meta-Schema and a valid basis, so these error reports are internal to each signatory's organization.

Establish: whose compilation it is, its Complementary Languages, and the expected outcome (compiled object or IR error report).

### G: Aether / IR / Timing Library / ε-error
**Perspective:** the single signatory that owns the artifacts.
> We're now in the last phase of detailing work in Mathematical Organization Theory. Every Aether artifact is internal to its signatory Organization / User / App / Agent.

Establish: whose IR it is. Then hand off to `/aether`, which inspects the intent.

## Rules

- **Frame, then route.** This skill frames, records and routes. Artifact files are built by the language skills, which keep their own workspace, validation and file rules. Don't duplicate them here.
- **Keep privacy boundaries.** From phase F on, error reports and Aether artifacts are internal to one signatory. In multilateral work, never show one signatory's F / G data to another.
- **Integer only.** Exact integers, closed `[LO, HI]` intervals, fixed-point over `CANOR_ONE = 1000`. Never use floating point.
- **Diagnose, never prune.** Every gap gets a status code and stays in the output: `CANOR_ERR_ARGS` (−1) malformed, `CANOR_ERR_RANGE` (−2) out of range, `CANOR_ERR_UNDEFINED` (−5) undefined or profile-unset, `CANOR_ERR_NOT_FOUND` (−6) missing prerequisite.
- **Assembly is side-effect-free.** Reading or writing CanorDB, or dispatching to a runtime, needs a contract in the `.fwp` / `.fws`. Without one, record the declared effect and don't perform it.
- **Don't invent profile-defined values.** Digest algorithm, dispatch, rollback / commit and rate-score rules stay **open items** until the profile sets them.
